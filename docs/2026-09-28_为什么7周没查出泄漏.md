# 为什么 7 周没查出泄漏（复盘）

> 建立 2026-09-28。起因：用户质疑 ——"V4 研究时我一再要求注意前视，你也验证、检查过了，
> 说没有这方面的问题，为什么近几天 180° 转向？"
>
> 本文回答这个问题。**结论是：不是"看漏了"，是三重失效叠加。** 而且其中一条
> （量尺坏了）是本次复盘新发现的、比泄漏本身更隐蔽的问题。

---

## 〇、一句话

**项目在 8/02~9/26 的 7 周里做过 14 次前视相关检查，每一次都放行了 ——
因为①量尺本身是坏的、②检查全落在"另一根轴"上、③唯一一次摸到病根被坏尺子判成"过拟合"并正式关闭。**

## 一、泄漏本身（先讲清楚"病"是什么）

`scripts/build_prediction_cache.py`（`MAX_TRAIN_SAMPLES` 处）：

```python
MAX_TRAIN_SAMPLES = 5000
_sel = np.arange(n_train - MAX_TRAIN_SAMPLES, n_train)   # ← 取时间上最后 5000 条
```

配合三个事实：

| 事实 | 数值 |
|---|---|
| 每月 2 个"采样日"（第 5、15 个交易日） | 每采样日全市场约 **2,825** 条样本 |
| 标签 y2 | 从采样日 D 起**未来 20 个交易日**的超额收益 |
| 5000 ÷ 2825 | ≈ **1.8 个采样日** |

⇒ 训练集实际是"**上个月最后约 2 个采样日**"的全市场样本；而它们标签（未来 20 日）
**正好覆盖被预测月的前半月**。**模型是在"已经知道这个月谁涨了"的前提下选这个月的股票。**

实测（`docs/2026-09_特征时效性与训练窗口的结构性约束.md`，2026-09 那个模型）：

```
训练窗口(12个月) n_train = 71,319 个样本（约 24 个采样日）
截断后实际用于训练的采样日 = ['2026-08-07', '2026-08-21']   ← 只有 2 天
```

**量级**（`docs/2026-09_回测IC异常排查清单.md` §2×2 对照，同 18 个月、同样本量、只换取样规则）：

| | 不 purge | purge 25 |
|---|---|---|
| **取尾部 5000（原状）** | **+0.4277**（18/18 为正） | −0.0001 |
| **随机抽 5000** | +0.0512 | +0.0136 |

## 二、失效 ①：量尺坏了 —— `analyze_monthly_ic.py` 的锚点晚了一整月

### 代码事实

`scripts/analyze_monthly_ic.py`（2026-08-02 写）原实现：

```python
last_date = SELECT MAX(date) FROM stock_daily WHERE date LIKE month||'%'   # ← 被预测月【月末】
```

而缓存语义是 **M−1 月末做的预测**，两处独立佐证：

- `scripts/build_prediction_cache.py`：`train_end_date` = `MAX(date) WHERE date >= 上月首日 AND date < 当月首日`（= 上月最后一个交易日）
- `logs/v4_70m_full_bt.log:43`：`[ 1/70] 2020-09 训练截止=2020-08-31`

⇒ **预测与评估目标整体错配一个月。** 这和"随便取个数"没区别。

### 实测（2026-09-28 独立复算，脚本只读缓存 + DB）

| 月 | n | **ref 锚（正确）= 上月最后交易日** | **M末锚（脚本实际）** | 旧 CSV 报的 `t2_ic` |
|---|---|---|---|---|
| 2026-03 | 2967 | **+0.6325** | −0.1574 | **−0.1577** |
| 2026-05 | 2969 | +0.1150 | +0.0849 | **+0.0862** |
| 2026-06 | 2970 | −0.0182 | +0.0957 | **+0.0956** |

**旧 CSV 与"错锚"吻合到小数点后 4 位**（2026-06：+0.0956 vs +0.0957）⇒ 证据确凿。

> **后果**：2026-03 那个月的**泄漏指纹明明是 +0.63**，被量成 **−0.16**（"模型反向"）。
> **能暴露泄漏的那把尺子，本身是坏的** ⇒ 泄漏 8/02 就"写在产物里"，却无人看见。

### 修法（2026-09-28 已执行）

锚点改为 `MAX(date) WHERE date < month||'-01'`（= 上月最后交易日），并加**自检断言**：

```python
if last_date >= ym + "-01":
    raise RuntimeError(f"[{month}] 锚点自检失败：ref_date={last_date} 未早于当月首日…")
```

旧 CSV 已备份为 `output/backtest_v2/monthly_ic_analysis_20260802_wronganchor.csv`（保留审计链）。

## 四、失效 ③：唯一一次摸到病根，被坏尺子判死

`V3研究方向与实验研究记录.md:262`（**2026-08-06**）原文：

> 生产 build 的 `MAX_TRAIN_SAMPLES=5000` 尾部抽样 ≈ 仅最后 **1.7 个采样日**（24 个采样日中）
> 根因：**2 组训练严重过拟合**，rank 目标在 2 组上不可靠

**它看到了截断，但把病因判成了"过拟合"，不是"标签泄漏"。**

然后是 ADR V3-04 的对照与关闭：

| 8/06 三向对照（70 个月） | 值 |
|---|---|
| 生产回归（5000 尾部抽样） | **+0.0105** |
| 全量回归（公平对照组） | +0.0127 |
| 差值（"抽样损失"） | **+0.0022 ≈ 0** |

**而坏尺子产出的 CSV（8/02）T2 均值 = +0.0106** —— 与"生产回归 +0.0105"吻合到 4 位。

⇒ **两臂都是用错锚的尺子量的**，都测成"接近 0"，差值自然 ≈ 0 ⇒
"抽样不是瓶颈" ⇒ **ADR 正式关闭（不优化生产抽样）**。

**用正确的尺子，那次对照的结论很可能完全相反**：尾部臂 100% 样本泄漏、全量臂仅约 8%。
**离真相最近的一次，被坏尺子判了死刑。**

## 七、教训 / 纪律（可复用）

1. **前视必须查两根轴**：特征轴（特征有没有用未来数据）+ **标签/样本轴（训练样本的答案有没有用未来数据）**。
   过去的检查 100% 落在第一根。
2. **"没测到" ≠ "不存在"**。任何检查都要声明"我测的是哪种泄漏、测不了哪种"。
   本文第五节的测试就是个反面教材：它只能发现龙虎榜泄漏，却被表述成"排除了前视"。
3. **异常好的数字要当 bug 查**。项目 2026-08-08 就在 `memory/kronos-ic-fake-signal-lessons.md`
   写下"**高到不合理的 IC 先假设有错，再假设模型有神功**" —— 但 8/21 面对"年化 73.4%、
   21.8 倍"时这条规则**没有触发**（当时归因于"电力板块暴涨 + 幸存者偏差"）。
4. **量尺本身也要被验证**。评估脚本必须带**锚点自检**：`ref_date` 必须早于被预测月首日。
   ⚠️ 注意本次订正的是"**错锚导致数字虚低**"，与"泄漏导致数字虚高"是**两个方向相反**的问题
   —— 它们叠加在一起，让症状互相抵消、更难发现。
5. **文件名/标签会固化假信心**。`去前视 summary_all.csv` 害了后面好几轮判断。
6. **同一根因对不同模型的作用可能相反**（本次的意外收获）：
   `X_tr[-5000:]` 对 **LightGBM 是"可利用的泄漏"**（横截面认脸 → 假 IC 0.23，看起来很强），
   对 **LSTM 是"断粮"**（序列学习需要时间跨度，只剩 1.8 个截面 → 真信号也学不到）。
   ⇒ **"T2 行、T4 不行"这个长期印象，本身是被同一个 bug 污染的。**
   去泄漏 + random 抽样后复算：**T4 IC20 +0.0423 (p=0.001) 强于 T2 +0.0292**。
