# P0 实施方案：择时-选股解耦 + 组合优化（2026-10-01）

> 配套文档：`2026-10-01_量化研究框架创新方向.md`（方向一、方向三）
> 目标：给现有选股框架**加两层**——配置层（权重）与决策层（总仓位），
>       成本最低、增量最大，且**回测框架已有部分基础**可复用。

---

## 〇、现状（代码级，已核实）

### 0.1 数据流
```
V4:   prediction_cache → select_stocks() → buy_list(等权) → submit_buy_signals() → SimEngine 等权买入
LLM:  沪深300 → Hs300Analyst → recommended(2只) → save_llm_recommendations() → SimEngine 等权买入
```

### 0.2 关键事实（已核实）
| 项 | 现状 | 位置 |
|----|------|------|
| **信号表** | **无权重字段**（仅 symbol/strategy_from/...） | `sim_buy_signals` |
| **生产买入** | **等权**（固定预算 或 现金/空缺数） | `engine.py:445`（`equal_weight_cash`） |
| **回测买入** | **已有权重函数**！ | `monthly_engine.py:151/159` |
| ↳ `ic_weighted_sizing` | 排名线性递减权重 | 回测用 |
| ↳ `min_variance_sizing` | **反比方差权重**（近60日） | 回测用 |
| **择时** | **无**（满仓）；V4 有 `use_t3_sizing`（波动率，未充分用） | `integration.py:231` |
| **回测引擎** | 支持 weight 字段 | `monthly_engine.py` |

**核心判断**：**"组合优化"在回测里有雏形、生产没有；"择时"两层都没有** →
**方案 = 把回测的权重逻辑搬到生产 + 新增择时层 + 回测先行验证**。

## 一、总体架构（两层解耦）

```
① 选股层（现有，不动）        TOP-N 个股（V4=10只 / LLM=2只）
        ↓
② 配置层（新增·方向一）       各股权重 w_i（Σw=1）   ← 组合优化
        ↓
③ 决策层（新增·方向三）       仓位系数 k ∈ [0,1]     ← 择时
        ↓
④ 执行层（改造）             买入金额 = 总资金 × k × w_i
```

**解耦价值**：选股（alpha）与配置/择时（beta/风险）**互不干扰**，可独立优化与验证。

## 二、方向一：组合优化（配置层）

### 2.1 权重方法（复用 + 新增）

| 方法 | 来源 | 公式/逻辑 |
|------|------|-----------|
| **等权（基线）** | 现有 | w_i = 1/N |
| **排名递减** | ✅ 已有 `ic_weighted_sizing` | w_i ∝ (N−rank+1) |
| **反比方差** | ✅ 已有 `min_variance_sizing` | w_i ∝ 1/σ_i²（近60日） |
| **风险平价**（新增） | 需实现 | 使各股**风险贡献** σ_i·w_i·(Σw)_i 相等 |
| **最小方差**（新增） | 需实现 | min wᵀΣw，s.t. Σw=1, 0≤w≤cap |

**约束**（A股特有，必加）：
- 单票上限 `w_i ≤ 0.15`（避免集中）
- **行业上限**（用 `tdx_stock_industry`：同行业合计 ≤ 0.30）
- 整手（100股）、资金约束

### 2.2 代码改造点（3 处）

**(1) 信号表加权重字段** —— `sequoia_x/simulation/models.py`
```sql
ALTER TABLE sim_buy_signals ADD COLUMN target_weight REAL DEFAULT NULL;
```
（向后兼容：NULL = 等权，老数据不受影响）

**(2) 选股后算权重** —— `scripts/v2_monthly_retrain.py::select_stocks` / `main_hs300.py`
```python
# 现有：buy_list = [symbols[i] for i in order]
# 新增：算权重（复用 monthly_engine 的函数）
from sequoia_x.model_selection_v2.backtest.monthly_engine import min_variance_sizing
signals = [{"symbol": s, "rank": r+1} for r, s in enumerate(buy_list)]
signals = min_variance_sizing(signals, engine, ref_date)   # 或 risk_parity（新增）
# 写信号时带 weight
submit_buy_signals(..., weights=[s["weight"] for s in signals])
```

**(3) SimEngine 按权重买入** —— `sequoia_x/simulation/engine.py::_execute_pending_orders`
```python
# 现有：budget = min(_ew_budget, cash_balance)   ← 等权
# 改为：
w = signal.get("target_weight")            # 从信号读权重
investable = cash_balance * k              # k = 择时仓位系数（方向三）
budget = (investable * w / sum_weights) if w else (investable / slots)
budget = min(budget, cash_balance)
```
（**保持向后兼容**：无 weight 时退回等权，老策略不受影响）

### 2.3 回测验证（先行）
`monthly_engine.py` **已支持 weight** → 直接改 `backtest_v2.py`/`monthly_engine` 的权重选择，**回测对比**：
```
等权 vs 排名递减 vs 反比方差 vs 风险平价
→ 比 夏普 / 最大回撤 / 换手率 / 行业暴露
```
**只有回测显著占优的方案才上生产**。

### 2.4 预期 / 工作量 / 风险
- **预期**：波动↓（高波动股权重降）、回撤↓、夏普↑0.1~0.3
- **工作量**：~3-5天（风险平价实现1天 + 信号表/SimEngine改造2天 + 回测对比2天）
- **风险**：协方差估计误差 → 用**收缩估计（Ledoit-Wolf）+ 滚动窗口**；**约束必须加**（否则退化为集中持仓）

## 三、方向三：择时（决策层）

### 3.1 择时信号（全用现有数据）

| 信号 | 数据源 | 计算 | 触发 |
|------|--------|------|------|
| **趋势** | `index_daily`(sh.000300) | 收盘 vs MA20/MA60 | 跌破 → 降仓 |
| **波动** | 指数/个股中位波动率 | 近20日年化波动 | 高波动(>分位80%) → 降仓 |
| **估值** | 全市场 PE 分位 | `stock_daily.peTTM` 中位 | 高分位 → 降仓 |
| **宽度** | stock_daily | 上涨股占比 / 涨停数 | 宽度差 → 降仓 |
| **资金** | `extra_features/fund_flow` | 全市场主力净流入(近5日) | 持续流出 → 降仓 |

**合成**：多信号**投票/加权** → 输出 `k ∈ {0.3, 0.5, 0.7, 1.0}`（**离散档位**，避免频繁微调→高换手）

**设计纪律**：
- **只避极端**（不做高频择时）——择时胜率天然低
- **仓位渐变**（如每次最多调 20%）——避免大开大合
- **明确空仓条件**（如趋势+波动双恶化）

### 3.2 代码改造点（2 处）

**(1) 择时模块**（新增）—— `sequoia_x/simulation/timing.py`
```python
def market_position_ratio(ref_date: str, engine) -> float:
    """返回仓位系数 k ∈ [0,1]（多信号合成）。"""
    # 趋势/波动/估值/宽度/资金 → 打分 → 映射到档位
```

**(2) 接入执行层** —— `v2_monthly_retrain.py` / `sim_update_hs300.py`
```python
k = market_position_ratio(ref_date, engine)
# 传给 SimEngine（新增参数 position_ratio）
sim = SimEngine(..., position_ratio=k)
# SimEngine：investable = cash * k（买不满则留现金）
```

**备选（更简单）**：择时放在**信号生成侧**（k<0.5 时只买 TOP-N 的 N×k 只）——但**不如执行层直接**。

### 3.3 回测验证（先行）
在 `monthly_engine` 加择时层，**回测对比**：
```
满仓 vs 择时（各信号单独 / 合成）
→ 比 年化 / 最大回撤 / 夏普 / 空仓期占比
```
**重点看极端行情**（2015股灾、2020疫情、2024-01）的表现。

### 3.4 预期 / 工作量 / 风险
- **预期**：**直击"满仓吃跌"**（004 LLM 9月 -9.92% 主因），最大回撤显著改善
- **工作量**：~3-4天（择时信号1天 + 接入1天 + 回测2天）
- **风险**：**择时误判**（该满仓时空仓，错失上涨）→ 用**档位 + 渐变 + 只避极端**缓解；**必须样本外验证**

## 四、分步实施路线（建议顺序）

| 步 | 内容 | 依赖 | 工作量 | 验证 |
|----|------|------|--------|------|
| **1** | 回测侧加**权重方法**（风险平价/最小方差）+ 对比 | 无 | 2天 | 回测夏普/回撤 |
| **2** | 回测侧加**择时层** + 对比 | 无 | 2天 | 极端行情回撤 |

| **6** | 上线观察（小步：先只接权重，再接择时） | 步5 | — | 实盘跟踪 |

**总工作量**：约 **8-10 天**（可先做步1-2 的**回测验证**，用真实数据判断是否值得上生产）

## 五、验证计划（吸取"回测好实盘差"的教训）

1. **回测先行**：所有改动**先在 `monthly_engine` 回测**，不直接改生产
2. **样本外**：Walk-Forward（滚动训练/测试），**不用全样本调参**
3. **极端场景**：单独评估牛/熊/震荡/股灾
4. **成本计入**：佣金/印花税/滑点/**换手率**（权重/择时都可能增换手）
5. **对照基线**：一律与"等权+满仓"对比，**没有显著优势就不上**
6. **dry-run**：生产接入前用 `--dry-run` 验证
7. **小步上线**：先接权重 → 观察 → 再接择时

## 六、风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| 权重方案过拟合 | 样本外 + 简单方法优先（风险平价>均值方差） | 信号表 `target_weight=NULL` 即回等权 |
| 择时误判错失上涨 | 档位/渐变/只避极端 | `position_ratio=1.0` 即回满仓 |
| 改动影响生产 | 向后兼容（NULL/默认值）+ dry-run | 参数开关 |

**回滚开关设计**：
```python
# SimEngine 新增参数均带默认值 → 不传即维持原行为
SimEngine(..., position_ratio=1.0, use_weights=False)
```

## 七、一句话总结

> **这两层的共同价值**：**不改选股逻辑**，只在"选出之后、买入之前"加两把旋钮——
> **一把定"每只买多少"（组合优化），一把定"总共买多少"（择时）**。
> 且**回测框架已有基础**（`min_variance_sizing` 等），**先在回测里验证，再上生产**。
