## 二、第二幕：转悲 —— 发现是"背答案"

### 2.1 触发点：一个"高得不像话"的数字

**2026-09-26**，生产预测缓存（V5，70 个月）的 T2 预测，对**下一个月已实现的 20 日超额收益**：

| 信号 | 均值 IC | ICIR |
|---|---|---|
| **生产预测缓存** | **+0.2304** | **1.288** |
| 20 日动量（无未来信息） | −0.0444 | −0.337 |
| 60 日动量 | −0.0649 | −0.468 |
| 5 日反转 | −0.0348 | −0.359 |
| **随机数** | +0.0018 | 0.095 |

**IC 0.23 + 99% 的月份为正** —— 在真实市场里**不可能**（学术界 IC 0.05 就算很强）。

> 这正是项目自己在 **2026-08-08** 写下过的规则：
> **"高到不合理的 IC 先假设有错，再假设模型有神功"**（`memory/kronos-ic-fake-signal-lessons`）。
> **但 8/21 面对"年化 73.4%、21.8 倍"时，这条规则没有触发。**

### 2.2 病根：`X_tr[-5000:]` —— 取"最近的 5000 条"

`scripts/build_prediction_cache.py`：

```python
MAX_TRAIN_SAMPLES = 5000
_sel = np.arange(n_train - MAX_TRAIN_SAMPLES, n_train)   # ← 取按时间排序的**最后 5000 行**
```

配合三个事实：

| 事实 | 数值 |
|---|---|
| 每月 2 个"采样日"（第 5、15 个交易日） | 每采样日全市场约 **2,825** 条样本 |
| 每条样本的标签 y2 | 从采样日 D 起**未来 20 个交易日**的超额收益 |
| 5000 ÷ 2,825 | ≈ **1.8 个采样日** |

**实测**（`docs/2026-09_特征时效性与训练窗口的结构性约束.md`，2026-09 那个模型）：

```
训练窗口(12 个月) n_train = 71,319 个样本（约 24 个采样日）
截断后实际用于训练的采样日 = ['2026-08-07', '2026-08-21']   ← 只有 2 天
```

**⇒ 所谓"12 个月滚动窗口"是被算出来之后丢掉的。每个月的模型，实际只用最近约 2 天的横截面训练。**

而那 2 天的"答案"（未来 20 日）**正好覆盖被预测月的前半月** ⇒ **模型是在"已经知道这个月谁涨了"的前提下选这个月的股票。**

> **打个比方**：考前复习，老师说"题库里有 12 个月共 7 万道题，但你只能做 5000 道"。
> 代码的做法是**只做最后两天的题** —— 而那两天的"答案"，恰好就是这次考试的题。

### 2.3 对照实验：只换"取哪 5000 条"

同 18 个月、同窗口、同样本量，**唯一变量 = 抽样规则**（`docs/2026-09_回测IC异常排查清单.md`）：

| | 不 purge | purge 25 交易日 |
|---|---|---|
| **取尾部 5000（原状）** | **A = +0.4277** ｜ 18/18 为正 | B = −0.0001 ｜ 10/18 |
| **随机抽 5000** | C = +0.0512 | D = +0.0136 |

**同数据、同模型、同样本量 —— 只换"取哪 5000 条"，IC 从 0.428 掉到 0.051。**

### 2.4 作废声明（必读）

> **70 月回测口径下的全部历史数字作废**（V4 +2077%、V5 +10081%、8/21 基准，以及"V5 比 V4 好 4.9×"）。
> **不是因为模型不好，而是因为它们衡量的是"背答案"的能力。**
>
> **仍成立**：同期做的**数据修复**是真修复（深市 **120.2 万行**价格口径被错存成后复权、
> amount **575 万行**补缺、指数取数走散、xdxr 死列等），与本次泄漏无关。

## 三、第三幕：更悲 —— 为什么 7 周没查出来？

> 这一节回答用户当时那句很关键的追问：
> **"V4 研究时我一再要求注意前视，你也验证、检查过了，说没问题，为什么现在 180° 转向？"**

### 3.1 失效 ①：**量尺坏了** —— IC 脚本的锚点晚了一整月

`scripts/analyze_monthly_ic.py`（2026-08-02 写）原实现：

```python
last_date = SELECT MAX(date) FROM stock_daily WHERE date LIKE month||'%'   # 被预测月【月末】
```

而缓存语义是 **M−1 月末做的预测**（两处独立佐证：`build_prediction_cache.py` 的 `train_end_date`；
回测日志 `[ 1/70] 2020-09 训练截止=2020-08-31`）⇒ **预测与评估目标错配整整一个月。**

**独立复算（2026-09-28）**：

| 月 | **ref 锚（正确）** | **M末锚（脚本实际）** | 旧 CSV 报的 |
|---|---|---|---|
| 2026-03 | **+0.6325** | −0.1574 | **−0.1577** |
| 2026-05 | +0.1150 | +0.0849 | **+0.0862** |
| 2026-06 | −0.0182 | +0.0957 | **+0.0956** |

**旧 CSV 与"错锚"吻合到小数点后 4 位。**
**⇒ 2026-03 那个月的泄漏指纹明明是 +0.63，被量成了 −0.16（还显示"模型反向"）。**

**修复效果**：同一缓存全样本 T2 均值 IC **+0.0106 → +0.1591** —— **修好的尺子立刻照出泄漏。**

### 3.3 失效 ③：**唯一一次摸到病根，被坏尺子判死**

`V3研究方向与实验研究记录.md:262`（2026-08-06）原文：

> 生产 build 的 `MAX_TRAIN_SAMPLES=5000` 尾部抽样 ≈ 仅最后 **1.7 个采样日**（24 个采样日中）
> 根因：**2 组训练严重过拟合**，rank 目标在 2 组上不可靠

**它看到了截断，但把病因判成了"过拟合"，不是"标签泄漏"。**

随后 ADR V3-04 的对照与关闭：

| 8/06 三向对照（70 个月） | 值 |
|---|---|
| 生产回归（5000 尾部抽样） | **+0.0105** |
| 全量回归（公平对照组） | +0.0127 |
| 差值（"抽样损失"） | **+0.0022 ≈ 0** |

**而坏尺子产出的 CSV（8/02）T2 均值 = +0.0106** —— 与"生产回归 +0.0105"**吻合到 4 位**。

**⇒ 两臂都是用错锚的尺子量的**，都测成"接近 0"，差值自然 ≈ 0 ⇒ "抽样不是瓶颈" ⇒
**ADR 正式关闭（不优化生产抽样）**。

**用正确的尺子，那次对照的结论很可能完全相反**（尾部臂 100% 样本泄漏、全量臂仅约 8%）。
**这是离真相最近的一次，被坏尺子判了死刑。**

### 3.4 8/21 那次"去前视"测试：在设计上就不可能发现任何东西

原文（`BACKTEST_PLAN.md:1500`）：

> **前视排除**：去前视版年化 **73.4%** vs 昨前视版 **73.8%**，几乎不变 → **提升与龙虎榜/涨停前视无关**

而**同一份文档**的三项核验第 2 条自己写着：

> **特征重要性**：龙虎榜/涨停/xdxr **gain=0.000%**（模型从不看情绪/分红维度）

**⇒ 唯一变量是"模型根本不看的两列特征"。** 删掉模型从不使用的列，结果当然不变。
**该测试的正确定名是"验证了龙虎榜特征没用"，而不是"排除了前视"。**

更糟的是产物文件叫 `去前视 summary_all.csv` —— **这个名字把假信心固化进了后续好几轮判断。**

## 四、第四幕：转喜 —— 三个**真的**好消息

### 4.1 ★ LSTM 不是包袱，是功臣（长期被冤枉）

**同一套 2×2 受控对照**（69 个月，M4/TOP10，同一政策，唯一变量 = 抽样 × 是否含 T4）：

| 抽样 | 模型 | 总收益 | 夏普 | 最大回撤 | 月胜率 |
|---|---|---|---|---|---|
| **tail** | T2-only | +167.2% | 0.65 | −45.7% | 49.3% |
| **tail** | **T2+T4** | **+345.4%** | **1.06** | **−30.4%** | **58.0%** |
| random | T2-only | −27.9% | −0.32 | −39.2% | 42.0% |
| random | T2+T4 | −18.5% | −0.20 | −45.9% | 46.4% |

**⇒ 同一个老模型、同一套数据、什么都不改，只是把 LSTM 加进融合**：
收益 **+178pp**、夏普 **+0.41**、回撤**改善 15pp**、月胜率 **+8.7pp**。

**端到端佐证**：random 口径下，**纯 T2 的 24 个配置全为负（0/24）**，
**加入 T4 后 24 个全部转正（24/24）**。

**稳健性**：`tail+T2+T4` 赢 `random+T2+T4` **24/24 配置且完全分离**
（前者最低 +145.1% vs 后者最高 −5.9%）；**剔最好 3 个月仍 +99.8%、剔 5 个月仍 +38.3%**
（对照：`tail T2-only` 剔 3 个月只剩 +5.3%）。

> ⚠️ **该稳健性数字的口径限定**（2026-09-29 核对时发现）：它是在 `monthly_returns` 这条
> **分析用中间序列**上算的，而该序列有 **#16 残差**（该格 全部月连乘 +274.9% vs 总收益 +345.4%，
> 缺口 30.8pp —— 见待办 #16）。**用于"两格相对比较"是有效的**（两格同口径），
> 但**不能当作绝对水平引用**。修正后重算待 #16 残差查清后进行。

**为什么之前没发现 —— 同一个 bug 对两个模型作用相反**：

| 模型 | 拿到"2 个市场截面 + 泄漏标签"会怎样 |
|---|---|
| **LightGBM** | 仍能在横截面上**利用泄漏**认脸 → 假 IC 看起来漂亮 |
| **LSTM** | 序列学习需要时间跨度，只剩 1.8 个截面 → **连真信号都学不到** |

**⇒ "T2 行、T4 不行"这个长期印象，本身就是被同一个 bug 污染的。**

### 4.2 ★ 生产现状就是四格里的最优，**不需要改任何东西**

生产配置 = **tail 抽样 + T2/T4 等权融合 + 硬止损 −12% + 月末收盘清仓** = 上表最优格。
这是第一次有**干净证据**支持"生产配置是最优的"。

> 代价：**没有"一行配置就能提升"的便宜可捡了** —— 那个"切 random"的预期收益是负的
> （09-28 我据 IC 提出"可能该切"，**实测被推翻**）。

### 4.3 ★ 模型**确实有真本事** —— 五路独立证据

| 检查 | 结果 | 说明 |
|---|---|---|
| 中性化后 IC | T4 **+0.0275（t=3.96）** | 剥掉行业/市值/波动后信号还在 |
| **风格匹配对照** | 扣掉风格后超额**保留 112%** | **不是"押对了板块"** |
| β 检验 | β≈0.93~0.96，**不高于全池** | **不是"买了高波动股票"** |
| 持有期对照 | 模型 TOP10 **+1.9%/月** vs 随机 −0.03% | 选出的股票确实更能涨 |
| 端到端 | **加 T4 让 24/24 配置由负转正** | 对组合是净加分 |

### 4.4 ★ 还有两处错误是**"让我们显得比实际差"** —— 白捡的

之前听的全是"数字虚高"，但也有**反方向**的：

| 方向 | 问题 | 修正后 |
|---|---|---|
| **虚低** | 回测用**末日开盘价**卖月末仓，生产用**收盘价** | E1 **+87.6% → +167.2%**（+79.6pp）｜B **+152.1% → +244.7%**（+92.6pp）；**回撤同时改善** |

| 虚高 | 训练标签泄漏 | ✅ 已修（`V2_TRAIN_PURGE_DAYS` 默认 25 + 防回归断言） |
| 虚高 | 池化 IC 放大 13~14 倍 | ✅ 已识别，改用逐月 IC |

| **生产配置（tail + T2/T4 融合）是最优格** | ✅ 真 —— 24/24 完全分离 |
| 持有期 +1.9%/月 的选股优势 | ✅ 真（配对 p=0.059，边界显著） |
| V4 +2077% / V5 +10081% / "好 4.9×" | ❌ **作废**（泄漏口径 / 口径未定义） |
| "T4 不行" | ❌ **作废**（口径污染） |
| "V4 期间已排除前视" | ❌ **不成立**（15 次全在另一根轴） |
| "组合层中性化值得做" | ❌ **证伪**（p=0.291、自助 CI 全跨 0、剔 3 个月归零） |
| "切 random 会更好" | ❌ **证伪**（钱口径 24/24 全输） |

### 5.2 为什么"回测 +345%/夏普 1.06"仍**不能当活钱年化**

1. **底层 IC 只有 0.02~0.04** —— 这个量级的信号，机构口径下对应的**实盘年化是"低双位数或更低"**
2. **回测是单一样本（69 个月）**，且优势高度偏斜（`tail T2-only` 剔 3 个月就只剩 +5.3%）
3. **统计功效不足** —— 项目自己算过：要在 80% 功效下检出观测到的 IC，**需要 60~150 个月**
4. **实盘还有回测覆盖不到的东西**：冲击成本、容量、真实成交

**⇒ 正确用法**：把 +345% 当作"**这个配置相对更好**"的证据，**不是**"能赚多少"的预测。

## 六、概念解释（大白话，供日后回看）

| 概念 | 大白话 |
|---|---|
| **IC（信息系数）** | 模型给的排名 vs 实际涨跌排名的相关性。0.03 算"弱但可用"，0.05 算强，**0.23 = 不可能** |
| **ICIR** | IC 的"信噪比" = 平均 IC ÷ IC 波动。0.4 算扎实 |
| **夏普** | 每承担一份波动，赚多少收益。1.0 左右算不错 |
| **泄漏（前视）** | 训练时用到了"当时还不该知道"的信息。**本项目的元凶** |
| **purge** | 训练时把"标签还没走完"的样本剔除。本项目默认 25 个交易日 |
| **池化 IC** | 把整段测试期叠起来算一个 IC（错的）。会把"月与月的整体涨跌"也算进去，**放大 13 倍** |
| **正解：逐月 IC** | 每个月各算一个 IC，再取平均 |
| **tail / random 抽样** | 5000 条训练样本怎么挑：**tail** = 只挑最近两天的（现状）；**random** = 从 12 个月随机抽 |
| **中性化** | 把"行业/市值/波动"这些**风格**影响剥掉，只看"选个股"的能力 |
| **Newey-West** | 一种统计修正，处理"相邻月份互相重叠"导致的 t 值虚高 |
| **TOP-N 事后超额** | 按预测取前 N 只，事后看它们平均涨了多少 —— **策略实际买入的东西** |
| **第二层脱节** | 连"TOP-N 事后超额"变好了，实盘组合也可能不跟（09-29 发现） |

## 七、教训与已固化的纪律

### 7.1 五条教训

1. **"高到不合理"要先假设有错，再假设模型有神功**
   —— 项目 8/08 就写下这条规则，但 8/21 面对"年化 73%"时**没触发**（当时归因于"电力板块暴涨"）
2. **尺子本身也要被验证**
   —— 花了 7 周才意识到"量错了"。**任何评估脚本都必须带"锚点自检"**
3. **IC ≠ 钱**（已实证 **3 次**，第 3 次我还押反了方向）
   —— **主指标要换成"实际买到的 TOP-N 表现"**；而且 TOP-N 也不是终点，**终审必须看组合层**
4. **"没测到" ≠ "不存在"**
   —— 任何检查都要声明"我测的是哪种泄漏、测不了哪种"
5. **有时错误的方向是反的** —— 不是所有 bug 都让你虚高（月末清仓价、IC 锚点都是"让你显小"）

### 7.2 已固化的机制（防止重犯）

| 机制 | 位置 |
|---|---|
| 训练集 purge 默认 25 + **防回归断言**（训练集最晚采样日越界即 raise） | `build_prediction_cache.py` |
| IC 脚本**锚点自检**（锚点必须早于被预测月首日） | `analyze_monthly_ic.py` |
| **标准评估流程**（①TOP-N 主指标 → ②IC/中性化/NW → ③组合层终审） | `V2_OPERATION_GUIDE.md` + `ic_by_horizon.py` |
| **月末链就绪检查**（含"陈旧产物会让干跑假通过"等 7 项） | `scripts/month_end_preflight.py` |
| **月度重训首跑验收**（非退化/分布漂移/换月稳定性） | `scripts/post_retrain_verify.py` |
| 融合权重统一到 `integration.fuse_ranks`（等权 0.5，三方同源） | `integration` |
