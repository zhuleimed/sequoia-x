# 特征维度变更操作规程（缓存重建 + 模型重训）

> **制定**：2026-10-07 ｜ **适用**：缩减/新增特征维度（如新增同花顺数据维度、砍掉相似冗余维度）
> **目的**：让后续**每一次**维度变更都遵循同一套规定，不再重蹈"缓存串味、静默用错模型"的覆辙
> **依据**：待办 #11（**年内三次实锤**）、`docs/2026-10-01_缓存重建与重训故障复盘.md`

---

## 0. 总则（一句话）

**维度变了 = 口径变了 = 所有旧产物作废。**

唯一可靠的做法是让**命名 / 版本号**去承载这个变化。
"靠人记得去删旧文件"一定会出错——待办 #11 就是同一件事被咬了三次
（09-27 / 09-28 / 10-07），每次都是"发现了→记录了→加了检查"，唯独命名没动。

## 1. 变更清单：加/减维度时**必须同步改**的地方

| # | 文件 | 改什么 | 为什么 |
|---|---|---|---|
| 1 | `sequoia_x/features_extra/build_extra_features.py` | 新组函数 `_xxx_features()` | 实际算特征 |
| 2 | 同上 | 注册进 `FEATURE_GROUPS` | 让框架认识这个组 |
| 3 | 同上 | **注册进 `_EMPTY_COLS`**（固定列名模板） | **固定列数契约**：数据面异常时全 0 兜底，保证输出列数恒定 → 拼接维度一致。漏了这步，异常时维度会变 |
| 4 | 同上 | **确认门控**：见 § 2 | 否则"注册即生效"，静默改生产行为 |
| 5 | `sequoia_x/model_selection_v2/labels.py` | **`FEATURE_VERSION` 必须递增**（如 6 → 7） | 它进缓存 hash key，是隔离新旧缓存的**唯一屏障** |
| 6 | 环境变量开关 | 仿 `FEATURE_V6_THS_FINANCE` 建新开关 | 默认不设 = 生产行为**逐位不变** |

## 2. 门控（最容易漏、后果最隐蔽的一步）

**坑在哪**：原实现是 `groups = groups or list(FEATURE_GROUPS.keys())` ——
调用方不传 `groups` 时默认取**全部组**。⇒ **只要把新组注册进 `FEATURE_GROUPS`，
所有调用方立刻用上它，无需任何显式开启，等于直接改了生产行为。**

**现行做法**（`build_extra_features.py`）：

```python
THS_FINANCE_ENV = "FEATURE_V6_THS_FINANCE"

def ths_finance_enabled() -> bool:
    return os.environ.get(THS_FINANCE_ENV) == "1"

def _default_groups() -> list[str]:
    gs = [g for g in FEATURE_GROUPS if not g.startswith("ths_")]   # 实验组默认排除
    if ths_finance_enabled():
        gs += [g for g in FEATURE_GROUPS if g.startswith("ths_")]
    return gs
```

**两处入口都必须用 `_default_groups()`**（2026-10-07 已核实均无遗漏）：
- `build_extra_with_flag()` → `build_extra_features.py:589`
- `build_extra_features()` → `build_extra_features.py:650`

**⇒ 新实验组的命名规则**：用 **`ths_` 前缀**，这样会被 `_default_groups()` 自动排除。
若新组不用该前缀，**必须同步改 `_default_groups()` 的过滤逻辑**，否则会静默启用。

### 2.1 「**减列**」型实验（2026-10-09 V6-C 新增的第二种形态）

**与"加组"不同**：减列**不改 `_default_groups()`**（组还在），而是改**该组实际输出的列清单**。
开关：`V6C_DROP_DIMS=<列名,...>`（见 `build_extra_features.py::v6c_dropped_dims()`）。

**★ 最容易漏的一步：`固定列数契约` 有两个入口，必须**同时**跟着变。**
- 正常路径：`_ths_finance_features()` 的返回值
- **异常兜底**：`_zero_features(group, dates)`（单数据面失败时输出全 0 列）

只改前者 ⇒ 数据面异常时兜底输出 5 列、正常路径输出 3 列 ⇒ **拼接维度错位**。
⇒ 现行做法：两处都走 `_group_cols(group)`。**新增任何"减列"开关都要照此办。**

**判据（改动后必须实测，不看 diff）**：
1. **不设开关 ⇒ 与改动前逐位一致**（列数、列名、保留列的值全对）
2. 设开关 ⇒ 列数正确 **且被保留的列与砍前逐位相同**（砍列不得扰动保留列）
3. 列名写错 ⇒ **抛错**，不静默忽略（静默忽略会得到"以为砍了、其实没砍"的假实验）
4. 版本号递增（本次 `FEATURE_VERSION` 5/6/7 → **8**），且**既有组合的版本号一个不变**

## 3. `FEATURE_VERSION`：最关键的一环

数据集缓存目录 = `data/cache/v2_dataset/{md5(参数)[:12]}`，参数键为：

```python
key_data = {
    "n_stocks": len(symbols),
    "sample_start": cfg.sample_start,
    "sample_end": cfg.sample_end,
    "window": cfg.window,
    "feature_version": FEATURE_VERSION,   # ← 维度变更靠这个隔离
    "market_state": include_market_state,
}
if include_extra:
    key_data["extra_features"] = True
```

- 版本号一改 → hash 变 → **新缓存目录，旧缓存并存不覆盖** → 新旧结果可随时回跑对照
- **加维度却不改 `FEATURE_VERSION` = 直接踩坑**（新旧数据混用，且不报错）

现有版本：`v4` 特征层换源 → `v5` 2026-09-25 列布局修复 → `v6` V6-A 同花顺财务质量 5 维（129→134）。
**`v5` / `v6` 缓存并存**，切换只看 `FEATURE_V6_THS_FINANCE` 是否 `=1`。

## 4. 缓存重建：全量 vs 增量复用

| 项 | 现行值 | 说明 |
|---|---|---|
| `REUSE_SAFE_DAYS` | **60**（默认）| 只复用"足够旧"的采样日（>60 天，其扩展数据不会再变），**近端一律重算** |
| `V4_REUSE_SAFE_DAYS=99999` | 实验用 | 所有旧采样日都落进"保鲜窗口" → 触发**全量构建** |

**为什么必须有这个约束**：缓存等价判据**只含参数 hash**（n_stocks / sample_end / window /
feature_version / market_state / extra_features），**不含数据状态**。
而扩展维度数据（fund_flow / finance / holders / consensus …）每次采集会**整体重写** ——
于是被复用的旧采样日带着**旧数据状态**算出来的值，最新一个月反而拿旧数据训练。

**血的教训**（2026-10-01）：增量复用让 A/B **两臂数据不同源**，实验失去可比性。
⇒ **换口径做 A/B 实验时，必须显式走全量构建**，不能让两臂悄悄用不同来源的样本。

## 5. T4 checkpoint 缓存命名（2026-10-07 起）

```python
# deep_lstm.py:549
checkpoint_path = cfg.model_dir_path / f"t4_checkpoint_{model_id}_f{X.shape[2]}.keras"
```

- `deep_lstm.py` 见到文件就 `load_model` 并**跳过训练** ⇒ **命名是唯一的防串味屏障**
- **必须带维度后缀**：`_f{特征数}`（如 `_f129` / `_f134`）
- 历史：无后缀命名被咬三次（88 维旧 ckpt 复用 / random 口径复用 / 129 维被 134 维命中）
- 旧的无后缀文件（70 个，`data/models/v2_selection/t4_checkpoint_cache_*.keras`）**已成孤儿，永不再读**

## 7. 重跑前的强制动作（防止坏月份被当"已完成"跳过）

1. **清主输出**：`output/backtest_v2/{预测缓存}.json` —— **先改名留档**（`.BAD_xxx_日期`）再删，便于取证
2. **清临时目录**：`output/backtest_v2/.cache_tmp_{stem}/` ——
   **只删主输出不够**！`_merge_temp_files` 会把 temp 里的 `month_*.json` 当新月份合并回主缓存
   （本次 temp 里躺着 **5 个**坏月份）
3. **启动方式**：`setsid nohup <命令> > <日志> 2>&1 < /dev/null &`
   判据：`ps -eo pid,pgid,sid,args` 里 **PGID 与 SID 都等于自身 PID**（`nohup &` 不够，会被整组杀）
4. **同一长任务只留一个重启入口**：多个守护者（定时任务 + 接力脚本）会打架

## 9.5 ★★ 缓存复用：**spec 判据**（2026-10-08 彻底方案）

### ★★★ 现行机制（2026-10-08 起，替代"往文件名加标签"）

**问题形状**：过去 4 次事故（09-27 / 09-28 / 10-07 / 10-08）共因只有一句 ——
**"这份缓存还算数吗"的判据是「隐式的、写在文件名里的、且不完整的」**；
而**轴是列举不完的**，只要靠"人记得还有哪些轴"，就一定会再漏。

**彻底做法**：把判据改成**显式的、由唯一函数生成的、加载时强制校验的 `spec`**。

| 机制 | 实现 | 作用 |
|---|---|---|
| **唯一判据函数** | `deep_lstm.compute_t4_spec()` | 保存与加载**共用** ⇒ 判据不可能不一致 |
| **文件名带 spec 指纹** | `t4_checkpoint_{月}_f{维度}_s{种子}_h{spec指纹}.keras` | 任一输入变 ⇒ 名字变 ⇒ 撞不上 |
| **自描述 sidecar** | `{checkpoint}.spec.json`（完整 spec，人可读）| 产物自带"我是什么"，不靠猜 |
| **数据内容哈希** | `_data_sample_hash(X, y)` 抽样 256 行 | **不是 mtime** —— 数据被重写骗不过 |
| **源码哈希** | `_code_hash()`（`deep_lstm.py` + `tree_*.py`）| 改代码自动失效，**不靠人工升版本号** |
| **加载时强制校验** | `_checkpoint_spec_ok()`；不符 ⇒ **⚠️ 报警 + 丢弃重训** | **"存在"不再等于"有效"** |
| **体检命令** | `scripts/verify_t4_cache.py`（只读）| 随时可查：命名不符 / 无 spec / 孤立 / 重复 |

**spec 覆盖**：schema、model_id、window、n_features、n_samples、seed、
data_sample_hash、data_tag、code_hash、params（含 batch_size）。

**验证证据（2026-10-08 实测，含反向测试）**：同输入指纹稳定；改种子/月份/超参/数据集标签/
**换数据行** → 指纹全部改变；盘上 spec 一致 → 放行；**篡改 seed → 正确拒绝并报出差异字段**；
缺 spec → 拒绝。`verify_t4_cache.py` 跑通（238 文件、0 命名不符）。

**★ 新增因素时的正确做法**：把它加进 `compute_t4_spec()` 的字段，而不是"再往文件名贴一个标签"。
—— 这是本方案与过去做法的**本质区别**。

### ★★★ 改动前必做（强制，2026-10-08 因违反此条而再次翻车）

**在对"训练 / 数据 / 特征 / 配置"做任何改动之前，先回答一句话：**

> **「这次改动，会让哪些已经存在的缓存产物变成『口径不同』？」**

把答案**列出来**（不要只在脑子里过），逐项处置：

| 处置方式 | 何时用 |
|---|---|
| **改 key / 改文件名**（让它撞不上） | **首选** —— 靠命名隔离，不依赖人的记性 |
| 归档旧产物 | key 改不了时的兜底；必须在**改动同一次**做掉 |
| 显式登记"本轴尚无防护" | 暂时不动时**必须写明**，并留下"何时会咬人" |

**为什么写成强制清单**：2026-10-08 我给 T4 加了随机种子（= **改变了训练制度**），
却没把"10-07 那批无种子 checkpoint"当回事 ⇒ 它们与新的 `_f134` **同名** ⇒
B 臂 t4-only 的 69 个月**全部恢复了旧的无种子模型**，一轮实验作废。
**同一页文档里本来就写着"要穷尽同类轴"**——写了规则却没在改动的那一刻用它。**规则只有被"改动前"读到才有用。**

**★ 一句自查话术（每次改完训练/数据管线后照念）**：
> **"我刚改了训练方式，那么——之前训出来的模型/缓存，现在还算同一个东西吗？"**
> 若答案不是斩钉截铁的"算"，就必须改 key 或归档。


**背景**：待办 #11（"checkpoint 缓存 key 粒度不足"）**年内实锤四次**（09-27 / 09-28 / 10-07 / **10-08**）。
前三次都只修/绕过**一个轴**，每次换到另一个轴就复发。**10-08 这次代价最大**：
A/B 两臂的全套回测（约 9h 机时）结论作废。

**"缓存里的东西会陈旧"至少有三个独立轴** —— 每次都要逐轴排查，不能只修你当次发现的那个：

| 轴 | 何时失效 | 现在的防护 |
|---|---|---|
| ① **特征维度** | 增删特征列 | `t4_checkpoint_{月}_f{维度}.keras`（10-07 加）|
| ② **数据集/数据版本** | 扩展维度数据被重新采集（`fund_flow`/`finance`/… **每次采集整体重写**）；数据集缓存的 hash **只含参数、不含数据状态** | ✅ `_d{指纹}`（**10-08 三次修复**）：指纹 = 缓存目录名 + `X.npy` 的 mtime/size ⇒ **参数变或数据被重写，指纹都会变**。实现在 `build_prediction_cache.py::_dataset_fingerprint()`，由 worker 传入 `train_lstm(data_tag=...)` |
| ③ **训练随机性** | LSTM 无种子 ⇒ 同数据重训也是另一个模型 | `tf.keras.utils.set_random_seed(按月派生)`（10-08 加，已验证逐位可复现）|
| ④ **训练制度 / 代码版本** | 训练方式变了（如"无种子→有种子"），但缓存名一样 | `t4_checkpoint_{月}_f{维度}_s{种子}.keras`（**10-08 二次修复**：把种子写进名字）|

**★ ④ 是怎么被发现的（10-08 实例，务必读）**：
只加 `_f{维度}` 时，**10-07（无种子时代）与 10-08（有种子时代）训出的 `_f134` 同名**
⇒ B 臂 t4-only 的 **69 个月全部"从 checkpoint 恢复"了旧的无种子模型（0 次重训）**
⇒ 而 **t4 自检查不出**（旧 t4 也是非零的）⇒ B 臂结果作废，白跑 90 分钟 + 一轮回测。
**是靠"新缓存 vs 基座逐月比对 t4"才抓出来的**——这条比对应该固化为常规动作。

**再补两条通用纪律（由 ④ 得出）**：
5. **自检要能区分"有值"与"值对"**：`t4 非零`这种检查只防"全 0"，
   防不了"恢复了旧模型"。**跨版本比对产物**（新 vs 旧逐月/逐字段比）才是有效检查。
6. **不要把"日志 grep"当闸门**：loguru 会折行，`grep -c "关键词"` 会漏报/误报
   （本次实测出现过 `更新 0 条` 的误读，且 `symbols 不一致` 的漏报会让坏缓存混进回测）。
   **闸门要直接核对产物**（月份数、逐月 symbols、与基准的差异），不要数日志行。

**强制动作（修这类问题时）**：
1. 把上面三个轴（以及将来可能新增的：代码版本、配置版本、股票池版本）**列全**，逐个查一遍；
2. 查"缓存复用"是否成立时，**至少比对三项**：
   - 缓存文件的**日期**（`ls -l`）vs 当前数据集/配置的**日期**
   - 缓存是在**哪份数据集**上产生的（不是"样本数相同"就算相同 —— **样本数相同 ≠ 数据相同**）
   - 产生缓存的**代码/配置版本**
3. **日志里出现"从 checkpoint 恢复"时，必须看一眼那个 checkpoint 是哪天的** ——
   10-08 的教训：A 臂日志有 69 次"从 checkpoint 恢复"，我看了**次数**却没看**日期**
   （文件是 09-28、当次数据集是 10-06，差 9 天，中间还重新采集过数据）；
4. **把检查延伸到所有臂**：验证 B 臂的缓存复用时，**同时问"A 臂是不是也在复用？"**
   —— 10-08 就是只查了 B（用户点名的那个），漏了 A（复用得更严重，69/69）。

**核心纪律**：**修完一个轴 ≠ 这一类的病治好了。** 认定"根治"之前，先把同类轴穷尽。
