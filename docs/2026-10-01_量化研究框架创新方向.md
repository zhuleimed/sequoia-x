# 量化研究框架创新方向（2026-10-01）

> 目的：跳出"再加一个因子/策略"的微调思路，从**框架/范式层面**寻找创新空间。
> 基于**现有数据条件 + 算力资源**（36核CPU / 187GB内存 / **无GPU** / 日线为主），
> 梳理 6 个可落地的方向，并给出设计、可行性、工作量与风险。

---

## 〇、先诊断：现有框架停在哪一层

```
[数据] → [特征] → [模型] → [融合] → [选股] → [配置] → [风控/验证]
  ✅       ✅       ✅        ⚠️       ✅       ❌         ⚠️
```

| 层 | 现状 | 评级 |
|----|------|------|
| 数据 | 全市场日线+估值(1636日)、财务(37年)、业绩预告(23年)、股东户数(13年)、研报(9年)、资金流(8年)、ETF(019) | ✅ 丰富 |
| 特征 | V5 129维（基础88 + 扩展41） | ✅ 成熟 |
| 模型 | V4: T2(LGBM) + T4(LSTM) + T1/T3；LLM-HS300；022 AlphaAgent 挖因子 | ✅ 多样 |
| **融合** | **`fuse_ranks`：T2/T4 秩平均（静态权重）** | ⚠️ 原始 |
| 选股 | TOP-N（V4=10只；LLM-HS300=2只） | ✅ |
| **配置** | **等权买入 / 满仓**（V4有T3波动率调节，但生产未充分用） | ❌ **空白** |
| **验证** | 回测 + IC排查（docs有记录） | ⚠️ 未体系化 |

**结论**：**强在"上游"（数据/特征/模型），弱在"下游"（配置/决策/验证）**。
**创新机会集中在：融合层、配置层、决策层、验证层。**

## 方向一：组合优化层 —— 从"选股"到"配置"

### 1.1 现状与问题
- 选股后**等权买入**（V4: 10只等权；LLM-HS300: 2只等权）
- **问题**：同样10只股票，**不同权重**的夏普/最大回撤差异巨大。等权**忽略了**：
  - 各股**波动率不同**（高波动股会主导组合风险）
  - 各股**相关性不同**（同行业股叠加暴露）
  - **风险贡献**不均（可能80%的组合风险来自2只股票）

### 1.2 创新设计
在"选股"与"下单"之间加一层**权重求解器**：

| 方法 | 思路 | 适用 |
|------|------|------|
| **风险平价 (Risk Parity)** | 使每只股票的**风险贡献**相等 | 最稳健、无需预测收益 |
| **最小方差 (Min-Variance)** | 最小化组合方差 | 低风险偏好 |
| **均值-方差 (Markowitz)** | max(μᵀw − λwᵀΣw) | 需收益预测（用模型输出当μ） |
| **Black-Litterman** | 市场均衡 + 观点（模型预测）融合 | 有先验观点时 |
| **最大分散化 (Max Diversification)** | 最大化分散度 | 降相关暴露 |

**约束**（A股特有）：
- 单票上限（如 ≤15%）、行业暴露约束、**换手率约束**（A股佣金+印花税+冲击成本）
- 整手限制（100股）、资金约束

### 1.3 数据可行性 ✅
- **协方差矩阵**：`stock_daily` 有 1636 个交易日 × 5000+ 只 → 完全够算（用近1年滚动窗口）
- **优化器**：`scipy.optimize` / `cvxpy`（CPU足够，无需GPU）
- 风险模型：可用**协方差收缩**（Ledoit-Wolf）或**因子风险模型**（用行业+规模因子）

### 1.4 预期增量
- **无需新数据、无需新模型**——纯在现有选股结果上做**免费增量**
- 参考业界经验：风险平价 vs 等权，年化波动可降 15-30%，夏普提升 0.1-0.3

### 1.5 工作量与风险
- **工作量**：~3-5天（优化器 + 约束 + 回测对比）
- **风险**：协方差估计误差（样本外衰减）→ 用**收缩估计 + 滚动窗口**缓解；A股行业集中度高，需加**行业约束**

## 方向二：元学习 / 模型路由 —— 从"固定融合"到"动态决策"

### 2.1 现状与问题
- `fuse_ranks(pred_t2, pred_t4)` = **T2/T4 秩平均**（**静态、固定权重**）
- **问题**：不同**市场状态**下，各模型的有效性不同：
  - 趋势市：动量型模型（T4 LSTM）可能更准
  - 震荡市：价值/均值回归型（T2 树模型）可能更准
  - 但**静态平均**无法利用这一点

### 2.2 创新设计
**元学习层**：用**二级模型**决定"何时信哪个模型"

| 方案 | 思路 |
|------|------|
| **市场状态条件权重** | 用大盘状态（趋势/波动/宽度）作为条件，动态调 T2/T4 权重 |
| **Stacking** | 把 T2/T4/T1/T3/LLM 的**输出作为特征**，训元模型（预测收益） |
| **模型选择器** | 分类任务：预测"本月中哪个模型会赢"→ 用之 |
| **在线学习** | 滚动更新权重（近期表现好的模型加权） |

**关键**：需要**"模型表现的历史记录"**（每个模型在各期的 IC/收益）→ 作为元模型训练数据。

### 2.3 数据可行性 ✅
- **模型输出**：V4 已存 `prediction_cache.json`（历史各月的 T2/T4 预测）→ 可回溯
- **市场状态**：`index_daily`（沪深300）+ 全市场宽度 → 可算
- **验证**：按"训练期元模型 → 测试期应用"严格走查

### 2.4 预期增量
- V4 已有多个模型（T2/T4/T1/T3），**只差调度层**
- 若"模型有效性随状态切换"成立，元学习可显著提升稳定性

### 2.5 工作量与风险
- **工作量**：~5-7天（需先积累"模型表现历史"）
- **风险**：元模型**过拟合**（样本少）→ 用**简单规则**（如状态→权重映射表）起步，避免复杂模型

## 方向三：择时-选股解耦 —— 从"满仓"到"仓位管理"

### 3.1 现状与问题（**最有价值的痛点**）
- 选股信号 → **满仓买入**（V4、LLM-HS300 皆满仓）
- **实证**：004 LLM 策略 9月累计 **-9.92%**，而同期沪深300 -12.26% → **绝对亏损主要来自"满仓吃跌"**
- V4 虽有 `T3波动率调节`（`integration.py:231`），但**未在生产充分利用**

### 3.2 创新设计
**两层解耦**：
```
择时层（宏观/大盘）  →  仓位系数 k ∈ [0, 1]
        ↓
选股层（个股alpha）  →  买什么（排名TOP-N）
        ↓
配置层（方向一）     →  各股权重 × k
```

**择时信号**（全用现有数据）：
| 信号 | 数据 | 逻辑 |
|------|------|------|
| 大盘趋势 | `index_daily`（沪深300 MA/动量） | 跌破均线 → 降仓 |
| 市场波动 | 指数波动率 / 个股中位数波动 | 高波动 → 降仓 |
| 市场估值 | 全市场 PE 分位数 | 高分位 → 降仓 |
| 市场宽度 | 上涨股占比 / 涨停数 | 宽度差 → 降仓 |
| 资金面 | `fund_flow` 全市场主力净流入 | 持续流出 → 降仓 |

**关键**：`k` 应**平滑变化**（避免频繁择时→高换手），并**只在极端状态大幅降仓**。

### 3.3 数据可行性 ✅
- 全部信号本地可算（index_daily + stock_daily + fund_flow）
- 无新数据需求

### 3.4 预期增量
- **直接改善绝对收益**（避开系统性下跌）
- 对 004 LLM 这类"满仓吃跌"的策略，**效果可能最显著**

### 3.5 工作量与风险
- **工作量**：~3-4天（择时信号 + 仓位层 + 回测对比）
- **风险**：择时**胜率低**（时点难判）→ 用**仓位渐变 + 只避极端**（不做高频择时）；需严格**样本外验证**

## 方向四：LLM 多 Agent 投研 —— 从"LLM 选股"到"LLM 组织"

### 4.1 现状与问题
- LLM 使用**很浅**：一个提示词 → 从300只选2只（单Agent、单任务、无协作）
- **问题**：单Agent**无自我质疑**、无专业分工、无记忆

### 4.2 创新设计
**多 Agent 投研团队**（借鉴 022 AlphaAgent 基础）：
```
┌─ 宏观Agent ──── 判断市场环境（牛/熊/震荡）
├─ 行业Agent ──── 分析行业景气与轮动
├─ 个股Agent ──── 分析公司基本面/估值/技术面
├─ 风控Agent ────【对抗】挑战个股Agent的结论
├─ 组合Agent ──── 汇总 → 最终决策（含权重）
└─ 复盘Agent ──── 事后归因（为何对/错）→ 反馈给前面Agent
```

**变体**：
| 变体 | 说明 |
|------|------|
| **辩论式** | 多空两方Agent辩论 → 裁决 |
| **假设-验证式** | LLM 提因子假设 → 代码自动验证（022在做） |
| **RAG 投研** | LLM 读**研报库**（reports 9年）+ 新闻 → 生成结论 |

### 4.3 数据可行性 ✅（部分）
- **研报全文库**（`reports`，2017-2026，9年，4346只）→ 可做 RAG 知识库 ✅
- **财务/业绩预告**（长历史）→ Agent 分析素材 ✅
- ⚠️ **新闻仅3个月**（`news`）、一致预期是快照 → 时效性素材受限

### 4.4 预期增量
- 从"LLM当分析师"→"**LLM当投研团队**"，是你已有LLM基础设施的**质变**
- 对抗性（风控Agent挑战）可**降低单Agent的过度自信/追高**

### 4.5 工作量与风险
- **工作量**：~10-15天（多Agent编排 + 角色提示词 + 汇总逻辑）
- **风险**：① **成本**（多Agent=多次LLM调用）；② **一致性**（Agent间结论冲突如何裁决）；③ 无GPU→本地模型不可行，**依赖API**

## 方向五：因果 / 稳健性验证 —— 从"相关"到"因果"

### 5.1 现状与问题
- 现状：回测验证（**相关**层面）
- **已知痛点**：你们 docs 里已有 **IC泄漏排查**（`2026-09-28_为什么7周没查出泄漏.md`）、**回测与实盘差异**（"从大喜到转喜"）→ 说明**验证体系**是薄弱环节
- **问题**：回测好看 ≠ 实盘有效（**过拟合、前视偏差、幸存者偏差、市场结构变化**）

### 5.2 创新设计
**体系化验证框架**：
| 层 | 方法 |
|----|------|
| **前视检查** | 时间戳严格性（特征只用 ≤T 数据；标注用未来但训练严格切分） |
| **样本外** | Walk-Forward / 滚动窗口 / 留出期 |
| **市场状态分解** | 牛/熊/震荡分场景评估（不只看全样本） |
| **因子正交化** | 去除共线性 → 找**独立**alpha（而非重复的） |
| **压力测试** | 极端行情（2015股灾/2020疫情/2024-01）复现 |
| **反事实/消融** | 去掉某模块看影响（Ablation） |
| **多重检验校正** | 大量因子 → 控制**假发现率（FDR）** |

### 5.3 数据可行性 ✅
- 全部基于现有数据（长期历史足够做多场景切分）

### 5.4 预期增量
- 解决"**回测好、实盘差**"的根本问题
- 让研究结论**可信**（而非自我安慰）

### 5.5 工作量与风险
- **工作量**：~5-7天（搭验证框架 + 应用到现有策略）
- **风险**：低（纯分析，不改生产）；但**可能否掉现有结论**（这恰是其价值）

## 方向六：跨策略组合配置 —— 从"多个独立策略"到"一个策略组合"

### 6.1 现状与问题
- 现有策略**各自独立、各占100万**：
  - 004 V4（`sim_v2.db`，100万）
  - 024 LLM-HS300（`sim_hs300.db`，100万）
  - 019 ETF 轮动（独立）
  - 021/022 因子研究
- **问题**：从**总资金**角度看，这是"**多个独立小账户**"，而非"**一个组合**"——无法做**跨策略风险预算**

### 6.2 创新设计
**统一的多策略配置框架**：
```
策略池: [V4, LLM-HS300, ETF轮动, ...]
   ↓ 各策略输出：目标持仓 + 预期收益/风险
配置层: 风险预算 / 相关性分散 → 资金分配
   ↓
统一账户: 一个总账户，统一风控
```

**关键问题**：
- 各策略**相关性**（同质化？）→ 若高度相关，组合无益
- **资金分配**：等权？风险平价？按近期IC？
- **统一风控**：总仓位、行业敞口合并计算

### 6.3 数据可行性 ✅
- 各策略有历史日结（`sim_account_daily`）→ 可算**策略间相关性**
- 但 ⚠️ 历史较短（024 刚建；V4 数月）

### 6.4 预期增量
- 从"**多个策略**"到"**一个组合**"（资产管理层）
- 若策略间低相关，**显著提升组合夏普**

### 6.5 工作量与风险
- **工作量**：~7-10天（需多策略都成熟）
- **风险**：**历史数据不足**（策略样本期短）→ 建议**待策略跑够半年再上**

## 七、优先级与路线图

| 优先 | 方向 | 工作量 | 增量 | 依赖 |
|------|------|--------|------|------|
| **P0** | 方向三 **择时-选股解耦** | 3-4天 | ⭐⭐⭐（直击满仓亏损） | 无 |
| **P0** | 方向一 **组合优化层** | 3-5天 | ⭐⭐⭐（免费增量） | 无 |
| **P1** | 方向二 **元学习/模型路由** | 5-7天 | ⭐⭐ | 需模型表现历史 |
| **P1** | 方向五 **因果/稳健性验证** | 5-7天 | ⭐⭐（方法论） | 无 |
| **P2** | 方向四 **LLM 多Agent** | 10-15天 | ⭐⭐⭐（质变） | LLM API |
| **P3** | 方向六 **跨策略组合** | 7-10天 | ⭐⭐ | 多策略成熟 |

**建议起步顺序**：
1. **方向三（择时）** + **方向一（组合优化）** —— 两者**互补**（一个控总仓位，一个控个股权重），
   且**成本最低、增量最大**，可**并行推进**
2. 再上 **方向五（验证框架）** —— 为上述改进提供**可信的评估**
3. 中期 **方向二（元学习）**、**方向四（LLM多Agent）**
4. 长期 **方向六（跨策略）**

## 八、资源约束提醒（贯穿所有方向）

| 约束 | 影响 |
|------|------|
| **无 GPU** | 深度学习受限（不用大模型/强化学习）；**适合** 树模型/统计/优化 |

## 九、一句话总结

> 你现在的框架**"上游很强、下游很弱"**：
> **模型已经很丰富，但"如何配置、如何决策、如何验证"这三层几乎是空白**——
> **最有价值的创新不在"再做一个更好的模型"，而在"给现有模型加上配置层、决策层、验证层"。**
